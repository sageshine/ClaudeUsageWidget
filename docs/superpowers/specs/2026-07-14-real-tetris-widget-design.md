# 진짜 테트로미노 위젯 UI — 설계 문서 (v2)

- 작성일: 2026-07-14
- 상태: 승인됨
- 이전 버전(단일 열 블록 쌓기, `2026-07-14-tetris-widget-design.md`)을 대체한다. 사용자가 실제로 본 결과가 "테트리스"보다는 "배터리 UI"처럼 보인다는 피드백을 받아 재설계했다.

## 배경 / 목적

기존 v1(세로 10칸 단일 열, 칸마다 단색 블록)은 실제 테트리스처럼 보이지 않았다. 클래식 테트로미노 7종(I·O·T·S·Z·J·L)이 위에서 떨어져 여러 열에 걸쳐 쌓이는 형태로 다시 만든다.

## 보드 규격

- 5칸(가로) x 10칸(세로) 그리드, 칸 크기 18px → 위젯 전체 90x180px
- 조각 모양은 고정 방향만 사용한다 (회전 없음 — 자동으로 쌓이는 시각화이지 플레이 가능한 게임이 아니다)

```python
SHAPES = {
    "I": ((0,0),(0,1),(0,2),(0,3)),
    "O": ((0,0),(0,1),(1,0),(1,1)),
    "T": ((0,0),(0,1),(0,2),(1,1)),
    "S": ((0,1),(0,2),(1,0),(1,1)),
    "Z": ((0,0),(0,1),(1,1),(1,2)),
    "J": ((0,0),(1,0),(1,1),(1,2)),
    "L": ((0,2),(1,0),(1,1),(1,2)),
}
```

## 색상

조각 종류별 클래식 테트리스 색을 쓴다 (I=하늘색, O=노랑, T=보라, S=초록, Z=빨강, J=파랑, L=주황). 위험도(경고/위험 임계값)는 색상으로 표현하지 않는다 — GAME OVER 오버레이가 그 역할을 대신한다.

## 조각 배치 규칙 (핵심 설계 결정)

**완전 무작위 열 선택은 쓰지 않는다.** 사용량%를 "채워진 칸 수 / 전체 칸 수"로 매핑하는데, 무작위 배치는 특정 열에 조각이 몰려 실제 사용량이 낮아도 보드가 일찍 topping-out(더 이상 못 놓음) 될 수 있다. 이는 위젯의 본래 목적(실제 사용량을 정확히 보여주는 것)과 어긋난다.

대신, 새 조각이 떨어질 때마다 **가능한 모든 열 위치 중 가장 깊이(낮게) 착지하는 열들을 후보로 추리고, 그중 무작위로 하나를 고른다.** 이렇게 하면 보드가 대체로 고르게 쌓이면서 시각적 변화(무작위성)도 유지된다.

**GAME OVER는 여전히 `headline_percent >= 100`일 때만 뜬다.** 조각 배치 운이 나빠서 보드가 일찍 꽉 차더라도(극히 드묾, 방어적으로만 처리) GAME OVER를 띄우지 않는다 — 실제 한도 소진과 화면 상태가 항상 일치해야 한다는 원칙을 지킨다.

## 채우기 목표 계산

`target_filled_cells = round(clamp(headline_percent, 0, 100) / 100 * 50)` (50 = 5x10 전체 칸 수)

- 목표가 늘어나면(사용량 증가) 목표에 도달할 때까지 조각을 하나씩 스폰해 떨어뜨린다.
- 목표가 줄어들면(한도 리셋) 애니메이션 없이 보드를 즉시 비운다 (v1과 동일한 정책).
- 위젯 생성 후 첫 `apply_state` 호출도 애니메이션 없이 즉시 그린다.
- 새 `apply_state` 호출이 들어왔을 때 조각이 아직 낙하 중이면, 그 조각을 즉시 착지 위치로 스냅시켜 보드에 반영한 뒤 새 목표를 향해 이어서 진행한다 (애니메이션을 중간에 버리지 않음).

## 애니메이션

- 조각은 보드 맨 위(0행)에 나타나 한 칸씩 0.3초 간격으로 착지 위치까지 내려간다.
- 착지하면 보드에 고정(잠김)되고, 목표 칸 수에 아직 못 미쳤으면 곧바로 다음 조각을 스폰한다.

## GAME OVER

v1과 동일: `headline_percent >= 100`이면 보드 위에 반투명 오버레이 + "GAME OVER" 텍스트, claude.ai에서 실제로 리셋될 때까지 유지. 오버레이가 떠 있어도 드래그·우클릭·호버는 막지 않는다.

## 모듈 구조

- **`tetris_pieces.py` (신규)**: 순수 함수 — 보드/조각 시뮬레이션 전체
  - `ROWS=10`, `COLS=5`, `TOTAL_CELLS=50`
  - `SHAPES`, `SHAPE_COLORS`
  - `empty_board() -> Board` (`Board = tuple[tuple[str | None, ...], ...]`)
  - `filled_cell_count(board) -> int`
  - `find_landing_row(board, shape_id, start_col) -> int | None`
  - `place_piece(board, shape_id, start_col, row_offset) -> Board` (불변, 새 보드 반환)
  - `choose_placement(board, shape_id, rng: random.Random) -> tuple[int, int] | None` (열, 착지행)
  - `choose_shape(rng: random.Random) -> str`
- **`tetris_logic.py` (기존 파일 정리)**: v1에서 쓰던 `filled_row_count`/`row_color`는 더 이상 아무 데서도 쓰이지 않으므로 제거한다. `is_game_over(headline_percent) -> bool`만 남긴다.
- **`widget.py` (전체 재작성)**: `tetris_pieces.py`/`tetris_logic.py`를 소비해 캔버스에 그리고 애니메이션을 담당. **`CharacterWidget`의 생성자 시그니처, `.apply_state(state, thresholds)` 시그니처, `.WIDTH`/`.HEIGHT` 클래스 변수는 v1과 동일한 형태로 유지한다 (값만 90/180으로 바뀜)** — 따라서 `app.py`는 이번에 전혀 수정할 필요가 없다.

## 테스트

- `tetris_pieces.py`는 Tkinter 없이 완전히 유닛 테스트 가능: 빈 보드에 착지, 기존 스택 위에 착지, 착지 불가 시 `None`, `choose_placement`가 가장 깊이 착지하는 열들 중에서만 고르는지, `rng`를 주입해 결정적으로 테스트.
- `widget.py`는 v1과 동일하게 실제 디스플레이에서 상태 전이(첫 호출 즉시 그림, 목표 증가 시 조각 스폰, 목표 감소 시 즉시 비움, 낙하 중 재호출 시 스냅 후 이어감, GAME OVER 표시 여부)를 확인한다.

## 범위가 아닌 것

- 조각 회전, 사용자 조작, 줄 삭제 — 여전히 범위 밖.
- 완벽하게 최적화된 배치(테트리스 AI처럼 빈틈 없이 채우기)는 하지 않는다 — "가장 깊이 착지하는 열 우선" 휴리스틱으로 충분히 고르게 쌓이는 정도면 된다.
